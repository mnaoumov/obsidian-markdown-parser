# obsidian-markdown-parser

## L1. Status: PRIVATE

This repository is private. Do not make it public, publish it to npm, link it from any public place, or mention it in a public issue, PR, forum post or README of another project. Making it public needs the Obsidian team's permission first, and asking for it is the owner's call.

## L2. Goal

A single incremental markdown parser for Obsidian-flavoured markdown, built on [`@lezer/markdown`](https://github.com/lezer-parser/markdown), that could one day serve both Obsidian's editor and its reading view. The Obsidian founder named Lezer as the target and the two hard parts (2026-10-13):

- **Live parsing** of a changing document: efficiency, partial states and resume points.
- **CSS-class compatibility**: today's editor uses a CodeMirror 5 token grammar, and themes and custom CSS depend on the classes it emits. The new parser must reproduce those class tokens exactly, or every theme breaks.

**Beyond Lezer (owner, 2026-10-13): compatible with all modern markdown parsers.** The Obsidian syntax (wikilinks and embeds, tags, `%%` comments, math, callouts, block ids, highlights, inline footnotes, task markers) is defined once, with one conformance corpus measured against Obsidian, and shipped as an extension for each ecosystem: Lezer (`@lezer/markdown`, the primary target), micromark + mdast (current unified/remark), and markdown-it. Each adapter is checked against the same corpus. Only the Lezer target also carries the editor's class-token compatibility layer. Scope confirmed by the owner (2026-10-13): all three, in that order - Lezer first, then micromark/mdast, then markdown-it.

## L3. Method: measured against the live app, never copied from it

- Behaviour is matched by differential fuzzing against a real Obsidian instance driven over CDP: the editor's class-token spans (read through `@codemirror/language`) and the metadata worker's `CachedMetadata`.
- Obsidian's code is proprietary: never copy code from the app bundle into this repository. Reading it to learn behaviour is allowed for plugin development under Obsidian's Terms (Restrictions, item iii).
- Open-source code the editor's behaviour descends from may be ported under its license, with the notice kept in [`THIRD-PARTY-NOTICES.md`](THIRD-PARTY-NOTICES.md). The class tokenizer ports the MIT CodeMirror 5 `markdown` mode and HyperMD, and uses CodeMirror 5's own sub-modes from `codemirror@5`.
- This work is the owner's own, done in his own time and never billed under his contractor agreement. It is intended as a gift to the Obsidian team, handed over with a written assignment if they take it into the core.

## L4. Phases

0. Class-span oracle against the live editor; measure the gap between plain `@lezer/markdown` and today's tokens. Stop here if the CM5 tokenizer's quirks prove impractical to reproduce. **Done 2026-10-13: go, with a stateful mapping layer.** The numbers are in [`docs/phase-0.md`](docs/phase-0.md), and the harness is in `phase0/`: `oracle.mjs` reads the live editor's tree over CDP, `corpus.mjs` builds the documents, and `gap.mjs` scores a Lezer mapping against the oracle. It stays only to reproduce the Phase 0 numbers: Phase 1 replaced it with the TypeScript oracle below.
1. Obsidian syntax extensions plus a class-compatibility layer, driven to 0 diffs on fuzzed documents. **Class layer done 2026-10-14: all 36,608 documents in eleven oracle corpora exact, two of them with tables, HTML, 30 fenced languages and nested lists, two more with markdown nested in markdown fences, two with code spans left open at the end of their line, and two with highlight color markers.** The numbers, the rules the editor follows and what is left are in [`docs/phase-1.md`](docs/phase-1.md). The class layer is a line tokenizer with copyable state in `src/editor/`, resumable from any line, not a Lezer grammar, because the classes come from a line tokenizer. The oracle is `scripts/oracle.ts` (reads the live editor over CDP), `src/oracle/` (corpus and scoring) and `scripts/oracle-diff.ts` (scores and shows diffs); its corpora in `oracle/` are the test oracle of `src/editor/highlight.test.ts`. **Syntax extensions done 2026-10-14:** the Obsidian syntax is defined once in `src/syntax/spec.ts`, with a shared conformance corpus in `src/syntax/conformance.ts` and the `@lezer/markdown` extensions in `src/syntax/lezer.ts`. `scripts/syntax-diff.ts` scores the tree against the live editor's classes, construct by construct. The rules, the scores and the differences are in [`docs/syntax.md`](docs/syntax.md). **CodeMirror 6 host done 2026-10-14:** `src/editor/language.ts` runs the tokenizer as a CodeMirror 6 `Language` that gives the mode the next line, emits the editor's tree shape and resumes after an edit from the last chunk whose reads, lookahead included, end before it. `src/editor/view.ts` renders the classes. Design and cost (`scripts/cm6-bench.ts`) are in [`docs/cm6-host.md`](docs/cm6-host.md). **Markdown blocks done 2026-10-14:** a block whose language resolves to the `markdown` mode runs the port without its editor layer, as Obsidian runs its fork of the CodeMirror 5 mode with the fork's default options. `src/editor/sub-modes.ts` registers the port as that mode. **micromark and mdast adapter done 2026-10-14:** `src/syntax/micromark.ts` is the syntax as a micromark extension and `src/syntax/mdast.ts` turns its tokens into mdast nodes. Both pass the whole corpus. On the 20,296 oracle documents, 19,509 give the same Obsidian nodes as the Lezer tree (`scripts/adapter-diff.ts`), and the rest are places where the two parsers' block structure differs, listed in [`docs/syntax.md`](docs/syntax.md). **markdown-it plugin done 2026-10-14:** `src/syntax/markdown-it.ts` is the syntax as a markdown-it plugin, with tokens named after `ObsidianNode` and each token's source range in its `meta`. It passes the whole corpus, and 19,546 of the 20,296 oracle documents give the same Obsidian nodes as the Lezer tree (`scripts/adapter-diff.ts --adapter markdown-it`); the differences are in [`docs/syntax.md`](docs/syntax.md#the-markdown-it-plugin). The `codemirror` dependency is pinned to the CodeMirror 5 release the measured Obsidian bundles (5.64.0 for 1.14.4), because its sub-modes' classes differ between releases. **Spec suites done 2026-10-14:** every adapter takes one set of options, a preset (`commonmark`, `gfm`, `obsidian`) with any of its flags overridden (`src/syntax/options.ts`). With the `commonmark` preset, micromark and markdown-it pass all 652 examples of the vendored CommonMark 0.31.2 suite and the Lezer tree passes 651, rendered by `src/syntax/lezer-html.ts` with the fixes in `src/syntax/lezer-commonmark.ts`. The GFM extension examples, the examples still failing and what each flag changes are in [`docs/spec-suites.md`](docs/spec-suites.md). **Quirks measured 2026-10-14:** `scripts/spec-oracle.ts` reads every spec example from the live editor, metadata worker and reading view into `oracle/spec-obsidian-1.14.4.json`, and `src/oracle/spec-quirks.ts` explains each of the reading view's 211 differences from the spec, pinned by its test. Four quirks are flags of `ObsidianQuirkFlags` in every adapter, off in every preset: `setextHeading`, `emptyListItem`, `looseList` and `softLineBreak`. **More quirk flags done 2026-10-14:** `characterReference`, `autolink`, `htmlComment`, `htmlBlock`, `linkDefinition` and `gfmTable` in every adapter, and `listItem` in micromark and markdown-it; `@lezer/markdown` keeps list item continuation internal. Their rules follow `remark-parse` 8, which Obsidian's reading view and worker run (`src/syntax/quirk-rules.ts`), and the live app, on 101 probe documents that `scripts/quirk-probe-oracle.ts` reads into `oracle/quirk-probes-obsidian-1.14.4.json`, pinned by `src/oracle/quirk-probes.test.ts`. The rest, and why each is no flag yet, are in [`docs/spec-suites.md`](docs/spec-suites.md#obsidians-quirks).
